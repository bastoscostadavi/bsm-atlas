# SQLite design and data ownership

This is the **installed paper-tested schema** (SQLite version 10), based on [BSM_ATLAS_AGENT_PROMPT.md](../BSM_ATLAS_AGENT_PROMPT.md), the [50-paper seed](../BSM_ATLAS_SEED.md) and a focused P01–P06 trial. It keeps the prompt's four core identities and adds relational child records for source evidence and repeated model structure. Current extraction and reconciliation coverage is recorded in [REVIEW.md](REVIEW.md).

## Three layers, one writer each

| Sole writer | Tables | What the rows mean |
|---|---|---|
| Python scripts | `papers`, `paper_versions` | Paper identity and each pinned version. Copy only seed-supplied ID, kind, title/authors as **seed metadata**, year, URL, filename and intended scope. Record local PDF availability and hash. The Markdown seed stays authoritative. |
| Paper-agent pipeline | `paper_profiles`, `paper_summary_revisions`, `paper_summary_assertions`, `paper_model_descriptions`, `paper_assertions`, `evidence_refs`, `paper_assertion_evidence`, `paper_assertion_corrections` | Codex extracts what an inspected **paper version** says into JSON; Python imports source records. A guarded correction command keeps an old/new snapshot when one claim must be revised. |
| Model agent / single model curator | `theory_families`, `theory_specifications`, their structural child tables, `theory_relations`, `theory_assertion_links`, `theory_assertion_rechecks`, `paper_theory_links`, `paper_theory_link_evidence` | Reconciled **model specifications**, structural parts, source links and per-citation decisions after a corrected claim. One curator writes these tables even if several agents propose model records. |

No agent edits another layer's rows. The paper Codex run has read-only repository access and returns structured data; `run_paper_agent.py` validates and inserts only paper-extraction rows. It can flag uncertain model identity in a source description but does not create a canonical model or paper–model link. A model agent reads paper records but does not rewrite them. If it finds a source-extraction error, it asks the paper pipeline to correct that source record. Scripts do not infer physics or write agent summaries. Schema migrations are reviewed by the model curator, applied by a script, and logged in `SCHEMA.md`; they do not silently change existing meanings.

## Proposed records and key fields

Every paper-derived or model child record has its own primary key and a foreign key to its parent. `paper_version_id` identifies an exact source version; `(model_id, revision)` identifies an atlas model revision. These are independent version histories.

| Record(s) | Information to store |
|---|---|
| `papers`; `paper_versions` | Stable `paper_id` and base arXiv ID; one `paper_version_id` per pinned version, with source kind, seed metadata, intended scope, URL, local filename, file status and hash. A later version gets a new row. |
| `paper_profiles`; `paper_summary_revisions`; `paper_summary_assertions` | One profile per inspected version: verified title/authors/dates/DOI, **separate** author abstract, inspected sections, extraction limitations, review status and reason for an expected zero model-link count. One summary-revision row per generated summary retains its text, producing run, date, coverage and review state. The junction identifies the detailed assertions supporting its claims. |
| `paper_model_descriptions` | One source-specific, possibly partial construction as presented by a paper version; its source label, covered sectors and completeness claim. It exists before any model reconciliation. |
| `paper_assertions` | One sourced contribution, result, assumption, field statement, interaction statement, relation or reported mechanism per row. Include optional source-description ID, subject/property, original notation, normalized value and transformation rule, conditions, **value status**, **basis** (source stated/assumed or agent inferred) and review status. A paper-level assertion may have no model description. |
| `evidence_refs`; `paper_assertion_evidence` | Exact equation, table, section or passage locator, with PDF and printed page where needed. The junction permits multiple locations per assertion; both sides must belong to the same paper version. Substantive checked assertions require evidence. |
| `paper_assertion_corrections`; `theory_assertion_rechecks` | Before/after source-claim snapshots and one review item per model citation affected by the correction. A curator must inspect the exact model target; no model physics is changed automatically. |
| `theory_families`; `theory_specifications`; `theory_aliases`; `theory_assumptions` | Family identity/parent relation; stable model ID plus atlas revision, name, family, covered sectors, defining restrictions, completeness and explicit SM/MSSM baseline status; repeated aliases and defining assumptions. A family is not a model specification. |
| `theory_regimes`; `theory_regime_relations` | Spacetime dimension, elementary/composite/effective description, EFT truncation/validity, and geometry. A model can have more than one described regime, with a qualified within-model correspondence. Major physics rows belong to one regime. |
| `theory_boundaries`; `theory_field_boundary_conditions` | Named boundary location and residual symmetry; field/component-specific boundary condition, chirality and source notation. A field and boundary must share a regime. |
| `theory_gauge_groups`; `theory_gauge_factors` | The whole group's stated direct-product/quotient/**unspecified** status, plus each factor, normalization and embedding. A factor's name alone does not determine the global form. |
| `theory_fields`; `theory_field_representations` | One field per row: superfield/component kind, spin, chirality, multiplicity and imposed field-reality condition. Separate representation rows refer to either one named gauge factor or the whole stated gauge group, with charges, representation reality and normalization where sourced. |
| `theory_symmetries`; `theory_symmetry_actions` | One symmetry per row: internal/spacetime, global/gauged, imposed/accidental, breaking and anomaly information. Separate action rows give field transformations or charges. |
| `theory_interactions`; `theory_interaction_participants`; `theory_parameters` | Defining operators, scalar-potential/superpotential/soft-term kind, original expression and conventions. Record **allowed**, **included** and **set to zero** separately; join each operator to its fields and their roles; parameters retain coefficient restrictions and normalization conventions. |
| `theory_vacua`; `theory_breaking_steps` | Vacuum or phase choices and their parameter assumptions; ordered breaking steps, order parameters, residual symmetries and whether each claim is assumed or established. A different vacuum need not create a new model ID. |
| `theory_relations` | Sourced restriction, extension, limit, shared-sector or effective-description relation between model revisions, with scope and reconciliation status. Uncertain equivalence remains a proposal. |
| `theory_assertion_links` | Connect a canonical model detail or relation to the paper-agent assertions supporting or disputing it. Model and assertion foreign keys are enforced; the specific `target_kind`/`target_id` is a provisional logical pointer that the curator must validate until typed foreign keys or a shared component key are added. Detailed model properties must be traceable through those assertions to exact source locations. |
| `paper_theory_links`; `paper_theory_link_evidence` | Model-agent reconciliation of a paper version (and optional source description) to a model revision. Store one queryable contribution role per link row, source label, scope and status; the evidence junction permits several supporting locations. A methods paper may have no link, with its reason in `paper_profiles`. |

Reported mechanisms and phenomenological claims stay **attributed paper assertions with conditions**; they do not become universal model flags. Missing information, explicit absence, ambiguity and source disagreement remain distinct. Partial frameworks or EFT operator bases need not be promoted to complete physical models.

## Workflow and current state

1. **Python** registers P01–P50 and pinned PDFs from the seed. This is done in the version-10 database; it does not count as paper extraction.
2. **Paper-agent pipeline** handles one pinned paper version per run, starting with P01 and then P02. Codex reads the PDF and returns structured JSON; Python validates and writes that version's profile, source descriptions, assertions and locators. It never writes canonical model tables.
3. **Model curator** handles one paper version per later run, after the paper agent has prepared it. It reads that version's source records and compares with earlier prepared papers and existing models, decides whether descriptions refer to the same model or distinct variants, creates structural model rows, and writes sourced paper–model links. It begins with P01, then P02 as a separate comparison run, and uses P03–P06 to test the schema before broader extraction.
4. **Validation scripts** check keys, coverage, evidence links and a reconstructible SQL export. They report errors; they do not invent missing physics values.

The seed-only database was migrated to version 7, then the populated database to versions 8, 9 and 10, with all 50 registered IDs, versions and local hashes preserved. `paper_versions` is Python-owned; profile and summary fields are in paper-agent tables. Paper and model-agent passes have now completed for P01–P50; their scientific review states remain unchecked or provisional. P02's earlier reset and rerun remain in the saved run history. Future source-backed schema changes belong in the decision log in `SCHEMA.md`. The concrete handoff is in [AGENT_WORKFLOW.md](../agents/AGENT_WORKFLOW.md), and current coverage is in [REVIEW.md](REVIEW.md).
