# BSM Atlas SQLite schema, version 10

The installed [SQLite schema](schema.sql) implements the four identities in the [original project prompt](../BSM_ATLAS_AGENT_PROMPT.md): `papers`, `paper_versions`, `theory_specifications` and `paper_theory_links`. The [data dictionary](DATA_DICTIONARY.md) lists every table and column with field meanings and status semantics; this file records schema decisions. Child tables make repeated physics structure, source assertions and evidence queryable. The [database design](DATABASE_DESIGN.md) assigns exactly one writer to each table. Version 10 contains source-scoped paper and model-agent dispositions for all 50 seed papers; [the review](REVIEW.md) records current counts and limitations.

## Identity and ownership

| Writer | Tables | Row meaning |
|---|---|---|
| Python | `papers`, `paper_versions` | Publication identity and a pinned source version. Title and authors here are seed hints; file status, size and SHA-256 describe a local file. |
| Paper-agent pipeline | `paper_profiles`, `paper_summary_revisions`, `paper_summary_assertions`, `paper_model_descriptions`, `paper_assertions`, `evidence_refs`, `paper_assertion_evidence`, `paper_assertion_corrections` | Codex returns source-specific JSON; Python validates and writes paper records. A targeted correction command preserves the old claim and evidence. Scientific review status stays separate. |
| Model curator | `theory_families`, `theory_specifications`, `theory_aliases`, `theory_assumptions`, `theory_regimes`, `theory_boundaries`, `theory_regime_relations`, `theory_gauge_groups`, `theory_gauge_factors`, `theory_fields`, `theory_field_representations`, `theory_field_boundary_conditions`, `theory_symmetries`, `theory_symmetry_actions`, `theory_interactions`, `theory_interaction_participants`, `theory_parameters`, `theory_vacua`, `theory_breaking_steps`, `theory_relations`, `theory_assertion_links`, `theory_assertion_rechecks`, `paper_theory_links`, `paper_theory_link_evidence` | Reconciled model revisions, their structural children, source support and decisions on citations affected by corrections. |

`paper_id` identifies a publication. `paper_version_id` identifies the exact source text. `(model_id, revision)` identifies one atlas model specification revision; an arXiv version change does not create a model revision. `paper_model_descriptions` record what a source presents before model identity is settled. Families, model specifications, description regimes, parameter choices and vacua have different meanings.

## Data dictionary and rules

| Tables | Key fields and use |
|---|---|
| `papers`, `paper_versions` | `paper_id`, base `arxiv_id`; `paper_version_id`, `version_label`, seed metadata, intended scope, source/PDF URLs, local filename, availability and hash. Multiple versions are separate rows. |
| `paper_profiles`, `paper_summary_revisions`, `paper_summary_assertions` | Verified bibliography and author abstract; inspected scope, limitations, extraction/review status and a reason when zero model links are expected. Summaries have independent text, revision, run, date, coverage and review state; their claims link to detailed assertions. |
| `paper_model_descriptions` | Source label, scope, completeness and source-specific description. This can be partial or unresolved and is never itself a canonical model. |
| `paper_assertions`, `evidence_refs`, `paper_assertion_evidence` | One source claim per assertion, with subject/property, source value, optional normalized value and `normalization_rule`, conditions, value status, basis and review state. Evidence stores section/equation/table/passage locator, PDF page and printed page. The junction allows several exact locations and enforces one paper version on both sides. |
| `theory_families`, `theory_specifications`, `theory_aliases`, `theory_assumptions` | Family hierarchy; stable model ID and atlas revision; completeness, sectors, baseline status, aliases and defining assumptions. An inherited SM/MSSM baseline is explicit or marked unresolved. |
| `theory_regimes`, `theory_regime_relations` | Dimension, elementary/composite/effective kind, EFT truncation/validity and geometry. A relation can record a qualified 4D/5D correspondence within one model revision without asserting unconditional equivalence. |
| `theory_boundaries`, `theory_field_boundary_conditions` | Named boundary and its position/residual symmetry; per-field or component boundary condition and chirality, including source notation such as `(+,−)`. Both the field and boundary must belong to the same regime. |
| `theory_gauge_groups`, `theory_gauge_factors` | Whole-group global form (`stated_direct_product`, `stated_quotient`, `stated_other`, `unspecified_in_scope`, or `not_applicable`), factors, normalization and embedding. A factor name does not establish a quotient. |
| `theory_fields`, `theory_field_representations` | Field kind (including superfield versus component), spin, chirality, multiplicity, imposed field reality and inherited baseline; whole-group or factor-specific representation, exact charge, representation reality and original notation. Each representation targets exactly one group or factor in the field's regime. A group-level singlet does not imply an enumerated factor list. |
| `theory_symmetries`, `theory_symmetry_actions` | Internal/spacetime and global/gauged distinctions, imposed/accidental origin, breaking/anomaly statement; per-field transformations or charges in the same regime. |
| `theory_interactions`, `theory_interaction_participants`, `theory_parameters` | Operators or potential/superpotential/soft terms, original expressions, coefficient restrictions; three separate flags for allowed, included and set to zero. Participant rows link an interaction to its fields and roles in the same regime, so Yukawa assignments can be queried. Parameters carry definitions, value status and normalization conventions. |
| `theory_vacua`, `theory_breaking_steps` | Regime-specific phase or vacuum assumptions; ordered breaking steps with order parameter, residual symmetry and assumed/established status. A changed vacuum alone does not force a new model ID. |
| `theory_relations` | Scoped restriction, extension, limit or shared-sector relation between model revisions; `reconciliation_status` preserves uncertainty. |
| `theory_assertion_links` | A model detail or relation supported, disputed or qualified by a paper assertion. Model and assertion FKs are enforced. `target_kind`/`target_id` remain logical pointers requiring curator validation. |
| `paper_assertion_corrections`, `theory_assertion_rechecks` | Before/after source-claim snapshots and one review item per model citation affected by that correction. The correction does not rewrite model rows. |
| `paper_theory_links`, `paper_theory_link_evidence` | One role per row for a paper-version/model-revision association; optional source description, source label, scope, status and exact supporting locations. A methods paper may have zero rows with the reason in its profile. |

The paper agent records a source's omission, for example an operator omitted from a displayed equation but acknowledged in the prose, as a **paper assertion with its stated scope**. It does not interpret omission as structural absence. `value_status` distinguishes specified, unspecified, explicitly absent, not applicable and conflicting information; `basis` distinguishes stated, source-assumed and agent-inferred statements; `review_status` tracks checking. Source notation and normalized notation coexist, and a normalization must state its transformation. Phenomenological claims and mechanisms remain attributed assertions with conditions.

Every substantive checked claim needs an evidence junction; SQLite enforces the version match, while extraction validation enforces coverage and locator quality. A detailed canonical claim needs a `theory_assertion_links` path to a paper assertion and its evidence. `validate_atlas.py` defines the allowed `target_kind` vocabulary and checks that each target belongs to the cited model revision. The logical target pointer remains a provisional structural limit and is validator-checked for the initial corpus.

## Historical paper trial and schema decision log

The initial schema trial used the locally stored pinned PDFs for P01–P06 and inspected the cited sections, equations and tables. It informed the schema before the full P01–P50 extraction. The following P01/P02 run counts describe that early trial, not the present corpus totals.

| Version | Source-backed distinction and design decision | Effect on earlier records |
|---|---|---|
| 1–5 | Earlier provisional identities and layouts. | No scientific extraction existed. |
| 6 | Separated Python registration from paper extraction; added source assertions/evidence and model child records. | Preserved 50 registered papers/versions; no physics data moved. |
| 7 | [P01 §2, eqs. 2.1–2.6](https://arxiv.org/abs/hep-ph/0011335v3) defines a singlet interaction and then chooses a vacuum; [P02 §1, eq. 1](https://arxiv.org/abs/1306.4710v5) omits the acknowledged singlet quartic from its displayed phenomenology potential. Record source treatment as scoped assertions, and add `normalization_rule` for differing coupling conventions; keep vacuum assumptions separate from structural terms. | No extracted rows required backfill. |
| 7 | [P03 Table 1](https://arxiv.org/abs/1106.0034v3) distinguishes Type I and II 2HDM by which Higgs doublet couples to fermion sectors. Add `theory_interaction_participants` so those assignments are queryable rather than expression-only text. | No model rows required backfill. |
| 7 | [P04 §2, eqs. 16–17](https://arxiv.org/abs/1005.5160v1) changes parity/charge-conjugation actions and Yukawa matrix restrictions while sharing the LR gauge setup; [P05 §2.1, eqs. 2.1–2.8](https://arxiv.org/abs/0910.1785v5) distinguishes general and Z3 NMSSM through zeroed dimensionful terms. Existing symmetry-action, parameter, operator-status and model-relation records cover these without new columns. | No model rows required backfill. |
| 7 | [P06 §§2–3, eqs. 27–30](https://arxiv.org/abs/hep-ph/0412089v2) relates a 4D composite description to a 5D bulk construction with UV/IR branes and field boundary conditions. Make major structural rows regime-specific; add boundary and within-model regime-relation records. Composite foreign keys prevent cross-regime field/operator and field/boundary joins. | No model rows required backfill. |
| 8 | [P01 §2](https://arxiv.org/abs/hep-ph/0011335v3) explicitly says the added real scalar does not transform under the Standard Model gauge group; [P02 §§1, 6.4](https://arxiv.org/abs/1306.4710v5) calls the real and complex variants singlets. Permit a representation to target either a whole gauge group or one factor, with exactly one target. Do not invent factor rows when the inspected source does not enumerate them. | Preserve all existing factor representations; add sourced whole-group singlet rows for the provisional P01/P02 model records. |
| 9 | The 50-paper run used dozens of free-text completeness labels that combined source coverage, structural completeness and caveats. Define separate finite vocabularies for source descriptions and model specifications, with exact interpretations in the data dictionary. Enforce both with `NOT NULL` and `CHECK`; validate agent proposals before insertion. | [Review each existing row](completeness_review_v9.json), retain its previous label in the audit, and replace only the status value. Keep all scope notes, source assertions, evidence and review states unchanged. |
| 10 | Linked paper assertions cannot be reset without breaking source-to-model citations. Add targeted correction history and a per-citation recheck queue. Keep assertion IDs stable; retain the old claim and evidence, recheck cited model rows individually, and leave physical model changes to explicit curator work. | Existing claims and model rows are unchanged. The new tables start empty; [migrate_v10.py](migrate_v10.py) makes a backup and checks the migrated database. |

The version-6 database contained only seed registration, so `import_seed.py` rebuilt it as version 7, preserving all 50 paper/version rows and local file hashes. Its migration refuses a version-6 database with any extracted rows. [migrate_v8.py](migrate_v8.py) makes a backup, preserves old factor-specific rows, and backfills the inspected group-level singlets with source-assertion links. [migrate_v9.py](migrate_v9.py) backs up the populated database and applies the row-reviewed labels. [migrate_v10.py](migrate_v10.py) adds the correction workflow without changing scientific rows. Later schema changes must record their distinctions and revisit affected records. The [agent workflow](../agents/AGENT_WORKFLOW.md) defines the first extraction trial and handoff.

The P01 paper-agent run imported one profile, one summary revision, one source description, 27 source assertions and 33 evidence references from `hep-ph/0011335v3`. P02's first run was partial because it conflated source extraction with cross-paper comparison. After a guarded reset and backup, a new P02 run imported one profile, one summary revision, three source descriptions, 28 assertions and 36 evidence references from `1306.4710v5`, with `ready_for_model` status. The structural validator passed. All imported claims remain `unchecked`; apparent source inconsistencies are attributed, not silently corrected. The v10 workflow handles one corrected assertion at a time; it does not replace a full paper-extraction revision lifecycle.

Separate one-paper model runs provisionally created `real-singlet-z2` revision 1 from P01, reused it for P02's principal real-singlet description, and created partial `complex-singlet-portal` revision 1 for P02's complex-field generalization. The phase-transition description is recorded as a scoped regime and vacuum of the real-singlet model. Those runs inserted 74 source-assertion links and five paper–model roles with 21 exact evidence links. Version 8 adds two whole-group representation rows and four source-assertion links; scientific review is still pending.
